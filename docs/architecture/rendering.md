# D2 authoring and rendering guide

## One script, two execution environments

**The repository-owned `scripts/render-architecture.sh` is the single rendering implementation.** The GitHub Actions workflow installs D2, calls the same script, uploads generated artifacts and (for permitted branches) commits SVGs back to the PR branch. CI must not maintain a second rendering command sequence.

### macOS (fish or bash)

```sh
brew install d2
bash scripts/render-architecture.sh           # Validate and render GitHub SVGs
bash scripts/render-architecture.sh --check   # Verify committed SVGs are current
bash scripts/render-architecture.sh --export  # SVG, PDF, PPTX for all diagrams
```

The script resolves paths relative to its own location, so it works from any current directory and is shell-independent when invoked via `bash`. Set `D2_LAYOUT=elk` to override the selected layout engine where useful. Generated SVGs are kept under `docs/architecture/rendered/`; presentation outputs are generated in `build/architecture/` (local or uploaded by CI). The `--check` option fails on stale or missing committed SVGs without modifying the tracked files.

## Supported D2 capabilities and intended use

- **Architecture boundaries:** grouped containers, labeled dependencies, layout with ELK, clear distinction between implemented and planned services.
- **Dynamic behavior:** D2 `shape: sequence_diagram` for ordered exchanges; annotate asynchronous and planned interactions explicitly.
- **State/process:** causal paths and rejection/exception flows.
- **Composition:** layers, scenarios and steps when a comparison or progressive explanation adds value.
- **Reusable styles:** use common classes/themes for meaningful deployment status and component roles rather than decorative duplication.
- **Navigation:** standalone SVG links and tooltips may be interactive, but GitHub image embeds do not reliably preserve them; provide adjacent Markdown links to source diagrams and documentation.
- **Animation:** use D2 multi-board exports when real time progression improves understanding, not as a substitute for a static architectural view.
- **Exports:** SVG for Markdown, PDF/PPTX for presentations/reviews, generated by the single script.

D2 syntax reference: https://d2lang.com/tour/intro ; export documentation: https://d2lang.com/tour/exports.

## CI contract and review

The `Architecture diagrams` workflow invokes `bash scripts/render-architecture.sh --export`. It validates every `.d2` source and produces SVG, PDF and PPTX outputs. The SVG files are committed back to the feature branch when GitHub permissions permit; binary exports are CI artifacts, not tracked source.

Every PR that changes structure, behavior, or deployment updates D2 sources plus Markdown explanation. Review actual SVG layout (not merely CLI success), and do not merge broken rendering. Reuse the same documented concepts; do not maintain duplicate manual images.

**Note:** `--check` compares exact rendered bytes. If D2 upgrades affect SVG serialization, regenerate all diagrams using a consistent D2 version and review the resulting diffs.
